**Resolved decisions (agreed before discovery, 2026-11-14):**

1. **Goal:** keep memory rich without bloating context: agents read an index and open only the entries they need. Nothing is trimmed or archived.
2. **Every append-only file lives in `ledger/`.** `global/decision-log.md` moves to `ledger/decisions/`; `global/` keeps only stable, human-approved narrative files.
3. **Layout:** `ledger/decisions/`, `ledger/learnings/`, `ledger/deliveries/`, each with one Markdown file per entry plus `INDEX.md`.
4. **INDEX.md is generated by the script and committed.** Agents never edit it by hand.
5. **`progress.md` keeps only Current state** (snapshot rewritten at harvest, budget 1,500 from task 020).
6. **Migration is a separate task** (`spine.py memory migrate`), planned after this one because it depends on the entry format fixed here.
7. **Replaces I6's archive approach** (rolling window + archive files). Re-scoring I5/I6 stays with `/spine-roadmap --review`.

**Resolved during discovery:**

8. **INDEX.md merges with `merge=union`.** The installer adds `docs/memory/ledger/*/INDEX.md merge=union` to `.gitattributes`. Git keeps both branches' new lines without a conflict; the next `spine.py memory index` restores order. The validator warns when an INDEX.md is stale.
9. **Decisions and deliveries are named by date + slug.** `ledger/decisions/2026-11-12-memory-digest.md` (reference `DEC 2026-11-12-memory-digest`) and `ledger/deliveries/2026-11-12-019-self-install-gitignore.md`. No counter, so two branches never pick the same ID; matches today's harvest marker `→ decision-log 2026-11-11`. Learnings keep `LEARN-NNN` (`ledger/learnings/LEARN-023-slug.md`) because `related_learnings` and harvest markers already use it.
10. **Transition: new layout, old files frozen.** Real projects follow this clone through `.spine`, so they get the new commands before the migrate task exists. Harvest always writes entry files; legacy `global/decision-log.md`, `ledger/learnings.md` and the `progress.md` delivery log stay read-only until `memory migrate` splits them. The digest shows both; the learnings recurrence check also searches a legacy `learnings.md` when present.
11. **Budgets cap each line, not the index.** Every entry needs a one-line `summary:` of at most 160 chars; the validator warns on missing or too-long summaries. No whole-INDEX budget (the index grows by design; the digest shows counts + newest 5; agents search it). Task 020's log-file budgets keep applying to legacy single files only, with a "legacy file — migrate" hint.
12. **Decisions can be superseded.** Optional frontmatter `superseded_by: <date-slug>`. Harvest sets it on the old entry when a new decision replaces it; INDEX.md marks those rows so agents skip them.

**Planner's choices (reversible, no question needed):**

- Each folder gets a seeded `_template.md` (same convention as `_task-template.md`); the index generator ignores files starting with `_` and `INDEX.md`.
- INDEX.md is a Markdown table, newest first, with a "generated — do not edit" line. Columns: decisions `Date | Decision | Status | Tags | Summary`; learnings `ID | Title | Tags | Recurrences | Summary`; deliveries `Date | Delivery | Task | Tags | Summary`. Titles link to the entry file. The learnings recurrence count comes from the `**Recurrences:**` list in the entry body.
- `progress.md` keeps its name (no rename churn); only the Delivery log section leaves it.

## Objective

Replace the three append-only memory files with per-entry folders under `docs/memory/ledger/`: `decisions/`, `learnings/` and `deliveries/`. Each holds one Markdown file per entry and an `INDEX.md` generated by `spine.py memory index`. Agents read the digest at Core SYNC, the index when they need history, and open only the entries they need. Harvest writes new entries without reading the old ones. `progress.md` keeps only Current state.

**Entry format (all three kinds):**

```yaml
---
id: 2026-11-12-memory-digest        # learnings: LEARN-023
date: 2026-11-12
title: Core SYNC reads the memory digest
summary: One line, at most 160 chars, shown in INDEX.md
tags:
  - area/memory
  - type/feature
task: 018-memory-digest             # empty when none
superseded_by:                      # decisions only, optional
---
```

The body keeps today's entry content: decisions use Context / Decision / Consequences; learnings use the LEARN template fields plus `**Recurrences:**`; deliveries use Branch and Description (citing execution evidence).

**Merging:** the installer adds `docs/memory/ledger/*/INDEX.md merge=union` to `.gitattributes`, so parallel harvests merge without conflicts; the validator flags a stale index.

**Legacy files** (`global/decision-log.md`, `ledger/learnings.md`, the `progress.md` delivery log) are frozen: still read by the digest and the validator, never written by commands.
